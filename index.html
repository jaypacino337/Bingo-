Mechanism

How a withdrawal works

  1. Deposit SOL, mint zSOL

    You send SOL and publish a commitment — a hash of a secret only you hold. The deposit is public, like any Solana transaction. Nothing is hidden yet.

  2. Choose your association set

    A set is a published list of deposits somebody is willing to vouch for. You pick which one to prove membership in. A broad set gives a larger anonymity crowd; a conservative one gives a stronger claim.

  3. Withdraw with a proof

    You withdraw to a fresh address and publish a zero-knowledge proof of two things: you know the secret behind some commitment in that set, and it hasn't been spent. Which deposit is yours stays private.

  4. The nullifier closes it

    Each withdrawal reveals a one-way nullifier derived from your secret. It proves this deposit was never withdrawn before without revealing which deposit it is. Double-spending is impossible; linking is not.

The distinction

Why zSOL isn't a mixer

The difference isn't the cryptography — it's what the protocol lets you assert.

 MixerzSOL
Hides your transaction graphYesYes
Lets you prove funds aren't from a hackNo — impossible by designYes, in zero knowledge
Honest users separable from stolen fundsNoYes, by association set
An exchange can accept the withdrawalTypically refused outrightThe proof is the evidence
Value to someone laundering a hackHigh — that's the problemNone. They can't produce the proof

The last row is the whole design. A thief can deposit — nobody can stop that — but no honest set will include their commitment, so they can never withdraw with a proof anyone accepts. Privacy stops being a shield for them and stays one for everyone else.

Association sets

Who decides what's flagged

Nobody, centrally — and this is the part most worth getting right. A set is just a signed list of deposit commitments. Anyone can publish one, and users choose which to prove against. Competing providers with different standards can coexist: a conservative set excludes anything within a few hops of a known hack; a permissive one excludes only direct, adjudicated theft.

The protocol itself takes no position. It verifies a proof about a set you named. That keeps the censorship decision outside the contract, where it can be argued with, forked, or ignored — rather than frozen into code nobody can amend.

The honest tradeoff: if every exchange converges on one provider's set, that provider becomes a de facto gatekeeper. Association sets move the trust problem; they don't erase it. Any serious deployment has to plan for set diversity, or it recreates the thing it was built to avoid.

Roadmap

Now

Protocol specification

Circuit design, commitment and nullifier scheme, association-set format. Public, reviewable, unimplemented.

Next

Reference circuits and devnet program

Groth16 circuits for membership and exclusion, an Anchor program on devnet, and a published test vector set.

Then

Independent audit and trusted setup

Circuit audit plus a multi-party trusted-setup ceremony with public transcripts. No mainnet deployment before both are complete.

Later

Set provider ecosystem

Tooling so more than one organisation publishes association sets, so the gatekeeping risk above stays hypothetical.

Questions

Straight answers

Can zSOL be used to launder money?
Not usefully. Laundering requires the output to be accepted somewhere, and the only thing that makes a withdrawal acceptable here is a proof of exclusion the launderer cannot produce. A pool with no proof attached is just a mixer, and that isn't what this is.
Does the protocol ever see my identity?
No. The contract verifies arithmetic over commitments. It never learns an address linkage, and there is no off-chain account, KYC step, or operator with a view of the mapping.
What if I'm excluded from every set unfairly?
You keep your funds — the deposit is always withdrawable to the original depositor without a set proof. What you lose is the anonymity, not the money. That's a deliberate floor: no set provider can strand a user's SOL.
Why Solana?
Proof verification is the expensive step, and it happens on every withdrawal. Cheap, fast execution is what decides whether the anonymity set grows large enough to be worth anything.
Is zSOL a token I can trade?
It's a claim on deposited SOL inside the pool, not a speculative asset. There's no separate governance token and no reason for one — a verifier contract doesn't need an asset to function.
